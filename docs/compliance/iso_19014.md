# ISO 19014 Compliance Mapping — Earth-Moving Machinery, Autonomous & Semi-Autonomous Machine Systems

See `docs/compliance/README.md` for what this document is and isn't.
ISO 19014 is a multi-part standard; this maps against the requirement
*areas* its parts cover (general principles, sensing/environment
representation, human-machine interaction, and safety functions),
rather than a clause-by-clause checklist, since the workspace doesn't
have the standard text itself to cite clause numbers against.

| Requirement area | Status | Where |
|---|---|---|
| Hazard identification & risk assessment for the automated functions | Blocked on external process | A formal risk assessment is an activity performed by qualified assessors against the *actual* machine and site, not derivable from source code. `spec.txt` and this workspace's module docs describe the hazards each safety function addresses (proximity, rollover, fatigue), but that is design rationale, not a certified risk assessment. |
| Perimeter/non-perimeter sensing for object detection | Implemented (software) | `tpt-t-construction-safety::perception` (360° LiDAR/radar/camera fusion), `tpt-t-construction-safety::classification` (human/light-vehicle/other-equipment), `tpt-t-construction-safety::tracking` (persistent track IDs across frames). Flagged gap: `docs/deterministic_execution_audit.md` notes `perception`/`tracking` aren't yet bounded-capacity/allocation-free like the rest of the safety-critical code. |
| Environment representation (terrain, obstacles, machine state) | Implemented (software) | `tpt-t-construction-terrain` (real-time grid reconstruction, slope/bearing-capacity, obstacle diffing), `tpt-t-construction-mine` (SLAM/EKF localization for GPS-denied areas). |
| Deterministic hazard response (warning/slowdown/stop) | Implemented (software) | `tpt-t-construction-safety::response` — dynamic zones (`warning_zones.rs`), zone classification and the required 50% slowdown / full stop response (`response.rs`), with a dwell-timer escalation and a validation suite specifically targeting false stops/false negatives (`tests/zero_false_stop.rs`). |
| Redundant/independent safety monitoring | Implemented (software, partial) | `tpt-t-construction-safety::tmr` (Phase 11): a generic triple-modular-redundancy voter for cross-checking three redundant readings of the same quantity. This is the *voting logic*; it presumes three actually-independent physical sensor channels to vote over, which is a Phase 12 hardware-integration concern (this workspace has no such wiring, only the decision function). |
| Rollover protection | Implemented (software) | `tpt-t-construction-rollover` — real-time tilt/CoG estimation and automatic brake application at a computed static-stability-factor margin. |
| Operator fatigue monitoring (where an operator remains in the loop, e.g. teleop) | Implemented (software) | `tpt-t-construction-fatigue` — PERCLOS eye tracking, steering pattern analysis, mandatory rest enforcement. |
| Human-machine interaction for teleoperation handover | Implemented (software) | `tpt-t-construction-teleop::safety_fsm` (the universal `AUTONOMOUS <-> REQUESTING_TELEOP <-> TELEOP_ACTIVE <-> RETURNING_TO_AUTONOMY <-> EMERGENCY_STOP` state machine) and `fault_handover.rs` (fault-driven handover triggers). |
| Functional testing under real operating conditions (dust, vibration, temperature extremes, varied lighting) | Blocked on hardware | Requires a physical machine and site; `tpt-t-construction-sim` validates the *logic* against synthetic sensor data (Phase 2), which is necessary but not sufficient evidence for this requirement. |
| Independent verification/validation and certification sign-off | Blocked on external process | Requires an accredited body's review; not something this repository can self-certify regardless of code quality. |

**Overall status:** every requirement area with a software-implementable
core has a concrete implementation to point to. Every requirement area
that inherently needs physical hardware or a named external assessor is
explicitly out of reach of this workspace, and is recorded as such
rather than glossed over.
